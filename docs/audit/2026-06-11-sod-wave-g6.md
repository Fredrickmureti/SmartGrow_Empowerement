# SoD Wave G6 — Members / role UX consolidation

**Date:** 2026-06-11
**Status:** Shipped (frontend only, no backend impact).

## Why

G3 deferred the Members UX consolidation as a separate wave. The
legacy flow forced an Owner to open a dialog (`EditRoleDialog`) just
to flip a member from `internal` to `staff`, and the invite dialog
used a plain `<Select>` for choosing the user type. Notion, Linear,
Vercel and similar platforms all let admins change roles inline and
pick role presets visually.

## What shipped

- **Inline role dropdown.** In `src/pages/Team.tsx`, the "Role" cell
  of the Internal Users table renders a compact `<Select>` instead
  of a read-only badge when the current user is allowed to manage
  the row. Changing the value calls the existing `handleUpdateRole`
  helper, which still writes to `user_roles` and emits the same
  `audit_logs` entry. Owner/super_admin rows and the protected
  organization owner remain non-editable (the badge falls back).
  The dropdown is filtered through `canManage()` so an Admin can
  never escalate someone to Owner.
- **Role-preset tiles in the invite dialog.** The old `<Select>` is
  replaced with two clickable cards (Admin vs Internal user). The
  Access Groups checklist still appears below when "Internal user"
  is selected — no change to invite payloads.

## What did **not** change

- `EditRoleDialog`, `BranchAssignmentDialog`, `BusinessAccessDialog`,
  `AssignGroupDialog`, `PromoteToInternalDialog`,
  `RemoveMemberDialog`, `TenantOwnershipTransferDialog` — all still
  reachable from the row's "More" menu. They cover the long-tail
  flows (branch grids, business access matrices, portal→internal
  promotion) that wouldn't fit inline.
- `user_roles` schema, audit logging, invitation RPCs — untouched.
- Permission gating is unchanged: `canManageMember()` decides who
  can see the inline dropdown and `canManage()` decides which roles
  appear in it.

## Verified

- TypeScript compiles; the inline change handler reuses the same
  `handleUpdateRole` path the dialog used, so audit + toast
  behaviour is identical.
- Read-only subscription users still bounce through
  `openUpgradeModal("team_management")` before any change runs.
- Architecture test `sod-coverage.test.ts` unaffected (no governance
  surface changed).
