# SoD Wave G3 — Governance Mode (Solo / Standard / Strict)

**Date:** 2026-06-11
**Status:** Shipped (migration + UI).
**Follow-up to:** `2026-06-11-sod-wave-g2.md`.

## Why

Wave G2 defaulted every action to `block`. For a fresh signup who is the only
person in the org, that meant being unable to approve their own work without
manually flipping every action in Settings → Governance. That contradicts how
Xero, QuickBooks, NetSuite, and other small-team ERPs ship — solo plans imply
self-approval; segregation activates as the team grows.

## What shipped

### Migration — `organizations.governance_mode`
- New column `governance_mode text NOT NULL DEFAULT 'solo'` with check
  constraint `('solo','standard','strict')`.
- Backfill: orgs with ≥ 2 active members → `standard`; everyone else stays
  `solo`.
- Trigger `trg_promote_governance_mode_on_member_add` on `user_roles` —
  promotes `solo → standard` the moment a second active member is added,
  writes `sod.governance_mode_changed` to `audit_logs`, never auto-downgrades.

### `governance_assert_not_self` rewrite

Same signature, same SECURITY DEFINER, same override flow. New evaluation
order:

1. Teardown bypass (unchanged).
2. Lookup explicit `self_action_policy` row by `(org, action, role | NULL)` —
   if present, that wins. **No regressions** for orgs that already configured
   per-action policy rows.
3. No explicit row → derive default from `organizations.governance_mode`:
   - `solo` + ≤ 1 active member → allow + audit
     (`sod.self_action_auto_allowed`).
   - `solo` + ≥ 2 members → allow (transitional; the trigger will promote on
     the next member-add).
   - `standard` → `warn` for owner/super_admin/admin; `block` for everyone
     else.
   - `strict` → `block` (Wave G2 behaviour).
4. Override consumption logic unchanged.

### UI
- `src/components/settings/GovernanceModeCard.tsx` — three-way radio (Solo /
  Standard / Strict) with plain-English copy and a live "N active members"
  badge.
- `src/components/settings/SelfActionPolicy.tsx` — copy reframed as "Advanced
  — per-action overrides", the 17-row matrix wrapped in a `<Collapsible>`
  hidden by default, badges now distinguish "mode default" vs explicit
  policy rows.
- `src/pages/settings/WorkspaceSettings.tsx` — Governance tab now opens with
  the mode card, then the advanced per-action card, then blocked-attempts
  queue.

## What was verified
- Migration applied cleanly; linter delta is pre-existing warnings unrelated
  to this wave.
- All existing `self_action_policy` rows still authoritative (explicit row
  wins over mode default).
- Override / co-sign / audit flow unchanged.
- Wave G2's seeded `admin_only` payroll rows continue to allow
  owner/admin/super_admin to self-approve payroll on legacy orgs.

## Deferred (intentional)
- **Members / role UX consolidation** (Notion-style row dropdown + bulk
  invite) — separate UX wave, no governance impact. Existing
  `src/components/team/*` dialogs continue to work.
- pgTAP runtime tests covering mode tiers — extension of the wave-G2
  follow-up.
- Vendor-bank-account sensitive-field framework — still open from G2.

## How to escalate
- Solo team using all features → leave on `solo`, the trigger handles
  promotion automatically when you invite someone.
- Two-person finance team → mode auto-promotes to `standard`; the owner can
  self-approve, staff cannot.
- SOX-style controls → owner flips to `strict` from Settings → Governance.
  Owners then need either a separate approver or a one-time co-signed
  override per action.
