**Date:** 2026-06-11
**Status:** Shipped (database + frontend), pgTAP runtime tests deferred.
**Scope:** Cross-module enterprise governance — prevents users from approving or posting their own work across Payroll, HR, Finance, Purchasing, Sales, Inventory, and Spend.

## What shipped

### Migration 1 — Self-Action Framework
- `public.self_action_policy` per `(organization_id, action_key, applies_to_role)` with mode `block | warn | require_cosign | allow`. Default `block`.
- `public.self_action_overrides` — append-only, immutable, owner/super_admin co-signed, expires in 1 hour, single-use.
- `public.governance_assert_not_self(actor, subject, action, org, entity_type, entity_id)` — central helper. Honours the teardown context; logs every block, every warn, and every override consumption to `audit_logs`; marks overrides `consumed_at` on use.
- `public.governance_assert_not_subject(actor, employee_id, action, ...)` — resolves the employee's `user_id` and delegates to `governance_assert_not_self`, used for self-benefit checks (e.g. approving a comp change for yourself).
- Seeded policies from `businesses.payroll_self_approval_policy` so existing behaviour is preserved.

### Migration 2 — Schema fill-ins
Added `approved_by`, `approved_at`, `submitted_by`, `submitted_at` to: `bills`, `bill_payments`, `payments`, `journal_entries`, `purchase_orders`, `expenses`, `customer_refunds`, `vendor_credit_notes`, `credit_notes`, `employee_compensation_history`, `employee_contracts`. All nullable.

### Migration 3 — Status-transition triggers
`BEFORE UPDATE` (or `BEFORE INSERT OR UPDATE` where the table has no status column) trigger per entity. When the row enters an "approved-equivalent" state, the trigger:
1. Requires `approved_by` to be set.
2. Calls `governance_assert_not_self` against the creator/requester.
3. Where the row targets an employee (`employee_loans`, `employee_compensation_history`, `employee_contracts`, `expenses` with `employee_id`), also calls `governance_assert_not_subject`.

Entities covered: `payroll_runs` (existing trigger rewired to use the new framework), `stock_adjustments`, `stock_transfers`, `leave_requests`, `timesheet_submissions`, `bills`, `bill_payments`, `payments`, `journal_entries`, `purchase_orders`, `expenses`, `employee_loans`, `customer_refunds`, `vendor_credit_notes`, `credit_notes`, `employee_compensation_history`, `employee_contracts`.

### Migration 4 — Canonical approve_* RPCs
`SECURITY DEFINER` RPCs that stamp `approved_by = auth.uid()` + `approved_at = now()` and write an audit log entry: `approve_bill`, `approve_bill_payment`, `approve_payment`, `approve_journal_entry`, `approve_purchase_order`, `approve_expense`, `approve_employee_loan`, `approve_customer_refund`, `approve_vendor_credit_note`, `approve_credit_note`, `approve_compensation_change`, `approve_employee_contract`. The triggers enforce the SoD invariants.

### Migration 5 — Approval-rule self-author flag (non-blocking)
- `approval_rules.requires_review` + `requires_review_reason`.
- Trigger flags (but does not reject) rules where `approver_type='user' AND approver_user_id = created_by`. Backfilled on existing rows.

### Migration 6 — Generic approval engine integration
- `BEFORE INSERT` trigger on `approval_history` calls `governance_assert_not_self(NEW.approved_by, approval_requests.requested_by, <entity>.approve, ...)`. This closes the bypass where a module routes through the generic workflow engine instead of a direct RPC.

## How to extend

To govern a new sensitive action:

1. Add `approved_by uuid` and `approved_at timestamptz` to the table (if not already present).
2. Add a trigger function that calls `governance_assert_not_self(...)` (and `governance_assert_not_subject(...)` for employee-linked rows) when the status transitions into an approved-equivalent state.
3. Add the action key to `SELF_ACTION_CATALOGUE` in `src/lib/governance/selfActionCatalogue.ts`.
4. Add the table to `ACTION_TO_TABLE` in `src/test/architecture/sod-coverage.test.ts`.
5. Optionally add an `approve_<entity>` RPC for a clean UI call site.
