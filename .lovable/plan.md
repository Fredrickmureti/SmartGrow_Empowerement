# How the Edge agent actually works (and why your paste was rejected)

## Two different credentials — you pasted the wrong one

The Edge stack has **two** secrets, and they are not interchangeable:

| Credential | Where it lives | What it authenticates | Where you see it |
|---|---|---|---|
| **Workstation secret** | `workstation.json` on the machine (written at enrolment, rotatable from the desktop **Identity & credentials** tab) | Desktop/agent → **AccrualFlow cloud** (Supabase edge functions: origins list, relay jobs, heartbeats) | Desktop app → Identity → "Rotate credential" prints it once |
| **Local agent token** | `~/.pos-agent-token` (32 random bytes hex, generated by the agent on first run, mode 0600) | **Browser → local agent** over loopback HTTP (`Authorization: Bearer …`) | Nowhere in the UI today — only by opening the file |

The IoT Box Agent field on `/platform/hardware/devices` wants the **second** one. The credential the desktop app showed you is the first one, so the agent's `validateAuth` compared it against the file contents, failed, and returned `401` — which the page reports as "Agent is online but rejected the token."

Right now the fix by hand is:

```bash
cat ~/.pos-agent-token
```

…and paste that string. (Confirmed from `agent/src/auth.ts`, `agent/src/server.ts`, `packages/desktop/src/pages/Auth.tsx`.)

## Request path

```text
Browser (https://www.accrualflow.systems)
  │  GET  /status /health /tls-info      ← unauthenticated
  │  GET  /usb/devices /discover         ← Bearer token
  │  POST /print /test /usb/print        ← Bearer token + fresh X-Edge-Nonce
  ▼
Local agent  http://127.0.0.1:8043  (and https://127.0.0.1:8443 when a loopback cert exists)
  ├─ Host header must be localhost/127.0.0.1 (anti DNS-rebind) else 421
  ├─ Origin must be in the allowlist (built-ins include https://www.accrualflow.systems)
  ▼
raw TCP → printer:9100     or     libusb → USB printer
```

The web client (`AgentClient`) probes `/status` every 30s, then calls `/usb/devices` once to decide "Authorized" vs "Online (no token)". Mutating calls serialize per endpoint, and on an https origin they can also be routed through the Supabase relay instead of loopback.

## Known rough edges this plan fixes

1. **No way to get the loopback token from the UI.** The desktop app already reads `~/.pos-agent-token` in `main.cjs`, but never surfaces it. Operators are expected to `cat` a dotfile — not enterprise-grade.
2. **Misleading failure text.** `_checkAuthorized()` returns `false` for *any* failure — 401, CORS rejection, mixed-content block, timeout — and the toast always blames the token. A blocked-by-browser case is currently indistinguishable from a wrong token.
3. **Nothing tells you the pairing is per-browser.** The token is stored in that browser's `localStorage`; a different browser/profile/machine needs pairing again.

# Plan

## 1. Desktop app — "Browser pairing" panel (Identity tab)

- New IPC `edge:agent:pairing` in `main.cjs` + `preload.cjs`, returning `{ token, tokenPath, authDisabled, baseUrl, tlsUrl }` (token read from `~/.pos-agent-token`, `authDisabled` from the agent env).
- New panel in `packages/desktop/src/pages/Auth.tsx`, visually separated from the cloud credential and explicitly labelled so the two can't be confused again:
  - Agent URL with a **Copy** button (`http://127.0.0.1:8043`).
  - Masked token (`••••••••` + last 4) with **Copy pairing token** and a **Reveal** disclosure, reusing the existing `IdChip` copy affordance/styles.
  - **Rotate pairing token** — deletes the file, restarts the supervised agent so a fresh token is generated, and warns that paired browsers must re-pair.
  - Inline copy: "Paste this into Platform → Hardware → Devices → IoT Box Agent, in each browser that prints from this machine."
- Copy nothing to clipboard implicitly; no token in logs or the support bundle.

## 2. Web UI — accurate diagnosis instead of a blanket token blame

In `AgentClient`, make the auth probe return a discriminated outcome (`authorized` / `unauthorized` / `blocked` / `unreachable`) instead of a bare boolean, keeping `isAuthorized()` for existing callers and adding `getAuthDiagnostic()`.

In `DeviceRegistryCard`'s **Test** handler, branch the toast:
- `unauthorized` → "Agent rejected this token. Copy the pairing token from the AccrualFlow Edge desktop app → Identity → Browser pairing." (also names `~/.pos-agent-token` for headless installs)
- `blocked` → explains the https → `http://127.0.0.1` block and points at the loopback-TLS / relay path
- `unreachable` → agent not running

Add a short helper line under the token input describing where the token comes from (desktop app first, dotfile second) so the wrong-secret mistake can't repeat.

## 3. Printer on `127.0.0.1:9100`

No new code needed — document and smooth the existing route:
- The **Loopback test print** block already on the hardware page sends ESC/POS init + text + cut to `127.0.0.1:9100` through the agent; use it to confirm the link before registering anything.
- For a permanent device: register it in the device registry with connection **Network**, address `127.0.0.1`, port `9100`, role `receipt_printer` (ESC/POS) or `label_printer` with a ZPL driver. The label pipeline then owns the envelope/geometry (ADR-0087/0088) — never hand-written ZPL from a page.
- Add a `docs/` runbook page: pairing steps, the `9100` device recipe, and a ZPL vs ESC/POS note (one physical printer, one role — a dual-language printer gets one assignment per role).
