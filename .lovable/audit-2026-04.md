## 8. Architecture invariants (read this before adding tables)

1. **Workspace = `organizations`**. Tenant chrome only: name, slug,
   logo (sidebar), timezone, date format, subscription, fiscal year.
   NEVER carries: email, address, tax_id, base_currency.
2. **Company = `businesses`**. The accounting/legal entity. Owns:
   legal_name, tax_id, registration_number, base_currency,
   address/phone/email, document branding (logo_url, email_display_name,
   email_reply_to), invoice/estimate/bill prefixes.
3. **Branch = `branches`**. Operational location inside a company.
   NEVER its own books. Carries `branch_id` on transactional rows for
   per-branch reporting; reports roll up to the company.
4. **Every new transactional table** must carry both `organization_id`
   AND `business_id`, both NOT NULL, both with FK + RLS. Add the table
   to `src/lib/businessScopedTables.ts` so the arch-guard enforces
   filter presence on every read/write.
5. **SCOPE-EXEMPT marker** is reserved for tables whose rows are
   intentionally workspace-wide (e.g. `approval_workflows`,
   `admin_audit_log`). Document the reason inline; the guard skips the
   query when it sees the marker.
6. **Documents always resolve branding from their own `business_id`**,
   never from the user's session. Use `useDocumentBranding(businessId)`
   on the frontend; on edge functions, pass `businessId` to
   `getOrganizationBranding`.
7. **All write-path edge functions** must call `checkSubscriptionActive`
   before performing writes. Read-only functions (render-report,
   keep-alive) are exempt.
